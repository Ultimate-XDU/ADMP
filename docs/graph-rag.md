# ADMP 图谱与检索

图谱由两部分组成：一部分保留文档、章节、条款和片段的结构层次；另一部分使用 LightRAG 从原文提取实体、关系。结构关系与跨文档引用用于发现线索，关系和检索结果保留原文来源。LangGraph 组织 Agent 检索流程，Cytoscape.js 在 `/graph` 页面展示图谱。

当前实现使用 NetworkX、NanoVectorDB 与本地文件持久化。运行模型为 Ollama 的 Qwen3.5:9b，BGE-M3 与 BGE Reranker 在当前部署中使用 CPU。无需为此启动新的 Docker 容器。

## 构建与覆盖

文档入库时登记实际解析出的片段与结构。选择文档并点击“构建所选文档图谱”后，才执行对应的语义实体、关系抽取；删除文档时移除对应来源。`GRAPH_AUTO_BUILD=1` 可以开启入库后的自动抽取，当前部署默认关闭。

`GRAPH_EXTRACT_SCOPE=all` 表示对选定文档的全部已解析单元抽取；`pilot` 与 `smoke` 只适用于局部试验。结构节点数量、已入库文档数量与已完成语义抽取的文档数量应分别查看。局部抽取不代表完整知识图谱。

## 检索模式

| 模式 | 流程 |
| --- | --- |
| `single` | 单轮混合检索与回答 |
| `graph` | 根据检索观察进行确定性图扩展与证据检索 |
| `agent`、`multi` | 模型选择检索、扩展、原文检查与停止动作 |
| `auto` | 根据问题与图谱可用状态路由，回退原因保留在轨迹中 |

`paths` 是检索子图的关系路径，`trace` 是实际执行的工具步骤。真正的顺序多跳需要前一跳观察提供下一跳线索，并由后续检索补齐必要事实；目录层级、调用数量或展示路径本身均不足以证明成功。

当前 Ubuntu 部署将工具调用上限设置为 6；单轮检索实际只执行一次。候选预算为 8，重排池为 16，生成上下文总预算为 5600 字符，每个证据窗口不超过 900 字符。一个来源可以有多个窗口。配置细节见 [运行说明](round2-runtime.md)。

最终打包优先使用实际命中的证据窗口，保留原文偏移与完整来源以便核验。跨文档引用沿已有引用方向扩展，目标文档仍通过实际检索获取证据；显示层的祖先路径不作为新的语义推理事实。

## 使用与验证

当前部署运行 `./scripts/admp-round2`，前端为 `http://localhost:5174/graph`，完整 API 为 `http://127.0.0.1:8788`。独立图谱 API 可通过 `scripts/run-graph-api` 启动，但不包含完整产品管理接口。

图谱与 Agent 链路当前使用文本证据。产品中的图文增强使用文本召回后的 PDF 页图，尚未接入视觉向量检索工具。

质量评测应固定文档范围、模型、候选与上下文预算，分别报告返回来源召回、实际生成上下文覆盖、来源精度与回答引用支持率。实验题、标签与运行结果应保存在独立评测环境。评测输出接口见 [检索评测说明](retrieval-evaluation.md)。
